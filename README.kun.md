## Why a fork, and why main

- **main, not 0.11.1**: main has `vertical-align` and a baseline for inline
  boxes (upstream #766, 2026-09-28), and sizes a line to contain an inline
  box the way CSS 2 § 10.8 does. In 0.11.1 a 30px box in 20px Ahem text
  gets a 30px line with the box sticking out 2px above it; on main the line
  is 34px. Images need both.
- **Local changes**: inline boxes that are kept with the content next to
  them, and that don't make the line taller (below). Without them, an
  inline element's start or end padding can end up on a different line
  from its text. Upstream lists "Margin/border/padding for inline spans" as
  not done yet in its Blitz tracking issue (#208).

Until 2026-10-01 this was a vendored copy inside kun (`third_party/parley`:
six of the crates, plus the changes as files in `patches/`). It became a
fork, next to kun at `../third_party/parley`, when kun's third-party
projects moved out of the repository; the changes became the commits on
`kun`, and updating upstream became a rebase.

## Local changes

The commits on `kun` after upstream's:

| Commit | What |
| --- | --- |
| Add InlineBox::line_break | `InlineBox::line_break` (`InlineBoxLineBreak`): `Auto` is upstream's behaviour (a soft wrap opportunity on each side of the box); `KeepWithNext` and `KeepWithPrevious` give the box no opportunity of its own and keep it on the line of the content after or before it. For `KeepWithNext`, an opportunity right before that content is taken before the box instead. Both the line breaker and the min/max-content measurer follow this. |
| Don't let inline box edges size the line | A `KeepWithNext` or `KeepWithPrevious` box (an inline's edge) takes up its width but adds nothing to the line's height, as an out-of-flow box doesn't. Upstream counts every in-flow box, so a 0px edge on the baseline made a line taller whenever the text's descent plus half-leading was negative (a `line-height` smaller than the font's), which WPT's `line-height-125` caught. |
| Wrap an atomic inline as the span it is in does | The line breaker and the min/max-content measurer only set the current `text-wrap-mode` from text, so an inline box first on a line (or in a layout) used the default, `Wrap`: in a `nowrap` span the line broke after it (WPT's `css/css-overflow/text-overflow-009.html`). An `Auto` box now takes the mode of its parent style (`parent_style_index`) before its opportunities are decided. A `KeepWithNext` or `KeepWithPrevious` box (an inline's edge) doesn't: the opportunity next to it belongs to the content beside it (WPT's `css/CSS2/linebox/inline-formatting-context-012.xht`). Marked `kun:` in `layout/line_break.rs` and `layout/data.rs`. |
| Give a line break's hanging whitespace | `LineBreakData::hanging_advance`: the part of the line's `advance` that is whitespace hanging past its end, which `commit_line` works out already (`LineMetrics::hanging_advance`). kun breaks the lines beside floats one at a time, each in its own room, and moves a line down to where floats leave more room when its content doesn't fit: the `advance` alone counts the hanging space, so a line that fits looked too wide. Only known once the lines were all broken before, from the lines' metrics, so kun broke them all again; with floats in the lines placed into the block formatting context as each line is final, which can't take a float back, that no longer works. Marked `kun:` in `layout/line_break.rs`. |
| Keep the shaping of layouts alike | `LayoutContext` keeps what shaping a layout's text gave (`shape/cache.rs`, `ShapeCache`), for the next layout with the same text, styled the same in what changes shaping (the font stack, size, width, style, weight, variations, features, locale, letter and word spacing), with its inline boxes at the same places and the same analysis (scripts, breaks, bidi levels); its other styles may differ, and each character and shaped cluster takes the new layout's style index (`ShapedText::set_style_indices` in `parley_engine`). A browser shapes the same text again as content is built again, and alike text in alike elements. Up to 2^18 characters, then it starts again. A kept shaping holds the copy of a font file it was made with (fontique loads a file again once nothing holds its copy, so two copies may be loaded). In a debug build every kept shaping is also shaped again and compared, fonts by their data (`same_shaping`). Marked `kun:` in `shape/mod.rs`, `shape/cache.rs`, `context.rs`, `builder.rs` and `parley_engine`'s `shape/shaped_text.rs`. |
| Make the line after a final break only where asked | `Layout::set_line_after_final_break`: whether the line after a forced break that ends the text (a newline last) is made. By default it is, as upstream has it: an editor puts the caret there. Made, it also counts in the layout's height: `finish_line` commits an empty run on it, so the height's check for an empty last line never sees one. CSS makes no line after the last forced break when nothing follows it (Blink's line breaker stops at the end of the content): `<div>a<br></div>` is one line tall, and Speedometer's Editor-CodeMirror (an empty line is `<div class="cm-line"><br></div>`) laid out one line less. kun makes it only in a text control's inner editor, where Blink adds a placeholder `<br>` to a value ending in a newline. Not made, the line is taken back once committed, before anything is yielded, so a caller breaking lines one at a time never sees it either. Marked `kun:` in `layout/line_break.rs`, `layout/data.rs` and `layout/layout.rs`. |
| Take the first font when it covers a cluster | `FontSelector::select_font` remembers the first font its query yields with a charmap (`first_font`, where upstream remembers only whether there is one, `query_yields_font`), and forgets it where upstream did: a new segment (its fallbacks), other families (or an emoji cluster's), other attributes. When that font covers the cluster completely it is taken without the query: the query takes the first font that covers a cluster completely, and fonts without a charmap are skipped, so the answer is the same. Most clusters are in the first font, and the query went through the families and their fonts for each one (4% of Speedometer's Editor-TipTap in kun). Blink's `HarfBuzzShaper` shapes a run with its primary font first, too. The query is `best_font`, moved out of `select_font`, so that a debug build runs it again each time the first font is taken and checks it gives that font (data, index and synthesis). Taking a font without a charmap first fails no test in kun: none of its test fonts lacks one. Marked `kun:` in `shape/mod.rs`. |
| Lay out tabs at tab stops | `StyleProperty::TabStops` (`TabStops`; `TextStyle::tab_stops`, `None` by default: a tab keeps its shaped advance, as upstream has it): the distance between tab stops and the least a tab advances, which the embedder works out (CSS `tab-size`, counted in the block container's space, which parley doesn't know). The line breaker gives a tab the advance to the next tab stop from where it is on its line (past the floats beside the line, `line_x`, and the indent) and takes the run again from the tab (`ShapedText::set_cluster_advance` in `parley_engine`); the min/max-content measurer works it out on each of its two lines. A stop nearer than the least advance is passed for the one after it, and with no tab stops (an interval of 0) the tab has only its letter spacing (Blink's `Font::TabWidth`). The shaper also shapes a tab as a space, so that it draws nothing: few fonts map U+0009, and the .notdef box showed. Marked `kun:` in `style/mod.rs`, `resolve/mod.rs`, `layout/mod.rs`, `layout/spacing.rs`, `layout/line_break.rs`, `layout/data.rs` and `parley_engine`'s `shape/shaped_text.rs` and `shape/shaper.rs`. |
| Size the font optically | `StyleProperty::OpticalSizing` (`TextStyle::optical_sizing`, off by default, as upstream has it): CSS `font-optical-sizing: auto`. The shaper sets the `opsz` axis to the item's font size before the item's own variations (which win where they set it), so a font with the axis is shaped and its run's coordinates are taken at it; a font without it ignores the axis. Items split where it changes, and the kept shapings tell it apart (`RunStyle`). Marked `kun:` in `style/mod.rs`, `resolve/mod.rs`, `shape/mod.rs`, `shape/cache.rs` and `parley_engine`'s `shape/shaper.rs`. |
| Break lines after soft hyphens with a hyphen | `StyleProperty::SoftHyphens` (`SoftHyphens`; `TextStyle::soft_hyphens`, `Break` by default: the opportunity after a soft hyphen is like any other and nothing is drawn, as upstream has it): CSS `hyphens`, `NoBreak` for `none` (an emergency opportunity at most, as `overflow-wrap` gives one) and `Hyphen(advance)` for the others, with the advance of the hyphen the embedder shapes and draws. The line breaker takes the opportunity after a soft hyphen (`CharacterFlags::is_soft_hyphen`, cached as `ShapedCluster::is_soft_hyphen` in `parley_engine`) as its style has it, an inline's start edge taking it too (an atomic inline's own opportunities are its own): with the hyphen at the line's end where it fits, or where the line has no opportunity before it; `LineMetrics::hyphen_advance` is then the part of the line's `advance` that is the hyphen, and in an RTL paragraph the line's items leave room for it on the left of `offset`. The min/max-content measurer counts the hyphen at the end of the fragment it ends. Marked `kun:` in `style/mod.rs`, `resolve/mod.rs`, `layout/mod.rs`, `layout/line.rs`, `layout/line_break.rs`, `layout/data.rs`, `layout/alignment.rs` and `parley_engine`'s `shape/data.rs` and `shape/shaped_text.rs`. |
| Share a layout's shaped text | `Layout::shaped_text`: a layout's `ShapedText` (re-exported) is an `Arc`, which what the embedder keeps of a layout holds, so it outlives the layout and is never changed under it: rebuilding the layout takes a new one where the old is held (`LayoutData::clear`), and breaking the lines copies it before changing a tab's advance where it is held (`Arc::make_mut`; a layout with tabs whose stops move pays one copy when its shaping is also kept). The kept shapings share it with their layouts instead of copying it, and a layout that takes one copies it only when its characters are styled otherwise. `GlyphRun::span` (`GlyphSpan`): where a glyph run's glyphs are in the shaped text (its shaped run and clusters), its direction and its line's spacing (`EffectiveSpacing`, now `PartialEq`), and `GlyphSpan::glyphs` walks them from the shaped text alone, as `GlyphRun::glyphs` does (`Glyphs`, which both use). kun keeps a line's runs as spans into the paragraph's shaped text instead of copying their glyphs (Blink's `ShapeResultView`). Marked `kun:` in `layout/data.rs`, `layout/layout.rs`, `layout/line.rs`, `layout/line_break.rs`, `layout/mod.rs`, `layout/spacing.rs`, `shape/mod.rs` (where it was), `shape/cache.rs` (likewise) and the tests' `canonicalize_layout_data`. |
| Walk a glyph run's clusters from its span | `GlyphSpan::clusters` (`SpanCluster`): the clusters `Run::visual_clusters` gives of the glyph run's style on its line (glyphs or not, a newline's too: the span keeps the run's clusters on the line and the style), their text and advance with the line's spacing, from the shaped text alone; `GlyphSpan::text_range`: where their text starts (the visually first) and how far it reaches, from the characters alone, without walking the clusters. `Run`'s `Clusters` and `GlyphSpan::clusters` walk the same graphemes with their atoms (`AtomGraphemes`, out of `Clusters`). kun works a run's clusters out from its span only when asked (selection, hit testing, `text-overflow`), not for every line it lays out. Marked `kun:` in `layout/line.rs`, `layout/run.rs` and `layout/mod.rs`. |
| Shape text a word at a time | `Shaper` shapes a segment a word at a time and keeps what shaping a word gave (`shape/words.rs`, `Words`): text is split before each space and after it, where a grapheme starts, and a word of up to 32 characters is kept by its text, an id for what font selection takes from each character's style (`FontSelector::font_style`, which parley's selector gives from `ShapeCache::font_styles`: the font stack, width, weight and style), the segment's script and the item's options. A word kept takes its fonts and harfrust's glyphs (in font units, clusters from the start of each run of one font) without selecting fonts or shaping; words of one font are put together into one `ShapedRun`, converted as a run shaped whole is (`push_run` takes harfrust's glyphs from either, `HarfGlyph`), so the result is the same, bit for bit. Only where shaping a word on its own gives what shaping the segment whole does: left to right, not Arabic or Syriac (harfrust's Arabic shaper looks at the text around a run), without features that are off unless asked for (`dlig`, `ss01`, ...), and with fonts whose rules take a space with the glyph beside it at most (`shape/space.rs`, `space_reach`: a lookup of a feature that may be on matching the space with the glyph before it or a glyph after it that can be other than a mark, a `kern` pair with it, or AAT tables; Gecko's `gfxFont::CheckForFeaturesInvolvingSpace` does the like for the whole font through HarfBuzz's `collect_glyphs`, which harfrust lacks). Such a font (`SpaceReach::Beside`) has the glyphs its rules of two take beside a space told apart, with what substitutions may make of them, positioning's apart from substitutions'; where a word ends or starts with one of them beside a space, `WordRuns` shapes the words around the space again as one: the word on that side for positioning, the words on both sides for a substitution (what it makes of the space may be shaped with the other side too), and the words on both sides of a space after a grapheme of several characters where a lookup skips marks (the `kern` table always does). The words shaped again as one aren't kept. A font whose rules reach further (`SpaceReach::Across`: a rule of three with a space, class 0 of a pair, a lookup skipping base glyphs, cursive attachment, a space as a mark, AAT, over 256 glyphs on a side) shapes the segment whole again (`ShapedText::truncate`). Arial and Times New Roman kern a few letters with a space and are shaped a word at a time; Calibri and Lato have a `calt` reaching across one. Up to 2^15 words, then the cache starts again; the ids of options and of font styles (2^12 each) start again with it. `LayoutContext::clear_shapings` forgets the words and the kept shapings, for fonts added. In a debug build every layout that took or kept a word is also shaped whole and compared (`same_shaping`); a new font selector sets its query's attributes, as the query may have shaped with another. Text is mostly the same words again (Speedometer's long text has 39,003 words, 9,917 of them distinct), and selecting fonts and shaping took most of the time text takes; Blink keeps whole runs of up to 30 characters (`NGShapeCache`), Gecko words (`gfxShapedWord`, after font selection). fontique's `SourceCache` keeps a font it prunes weakly, and loading it again while something still holds it takes the same blob: a kept word holds its font, and the font loaded again under another blob id is another font to the runs put together (`same_shaping` failed on a long text with many fonts). Marked `kun:` in `parley_engine`'s `shape/shaper.rs`, `shape/shaped_text.rs` and `shape/mod.rs`, in parley's `shape/mod.rs`, `shape/cache.rs` and `context.rs`, and in fontique's `source_cache.rs`. |
| Look line breaks up in a table | `analyze_text` finds the line break opportunities of a text under the default rules (one segmenter configuration, `SegmenterKey::DEFAULT`) in a table for characters up to U+017F and from U+2000 to U+203F (`line_table.rs`: Latin-1, Latin Extended-A and the commonest punctuation, `’ “ ” – — …`), by the class of the last character that isn't a space before each one, whether spaces are between them, and its class, as UAX #14's pair table does. The table is what ICU4X's line segmenter gives, generated from it by a test that fails when the table is out of date and prints it anew; an entry that changes with the characters around the pair (an opening quotation mark after spaces, LB15a; a closing one before them, LB15b) is left to ICU4X. A word (text between spaces) with a character outside the table, or such an entry, is given to ICU4X with the words on either side, and only its opportunities are kept. The tests compare every text of up to four characters of the classes, and long random ones, with ICU4X, and a debug build gives every text looked up to ICU4X whole too and compares. Speedometer's long text (French) takes 0.53 ms instead of 1.54 ms, giving no word to ICU4X. Blink's `LazyLineBreakIterator` looks pairs up to U+00AD in a table of its own, which differs from ICU in a few cases. `AnalysisOptions::skip_word_boundaries` (`LayoutContext::set_word_boundaries`, on by default): leaves word boundaries out, a fifth of the analysis, for text no one moves through by words with parley's clusters (kun's layout: its editing finds words itself; its address bar's `PlainEditor` keeps them). `LayoutContext::line_breaks_looked_up` counts the texts looked up and the words given to ICU4X, for tests. Marked `kun:` in `parley_engine`'s `analysis.rs`, `analyzer.rs` and `lib.rs`, and in parley's `analysis.rs` and `context.rs`. |

The vendored copy also trimmed the workspace (no `parley_dev`, upstream's
test harness), so that it loaded on its own: kun's `cargo fmt --all`
formats path dependencies too. With the full tree that isn't needed.

Not proposed upstream yet. Anything sent upstream is drafted first and
reviewed before it goes out.

## Updating

1. `git fetch` upstream (add it as a remote, fetch only) and rebase `kun`
   onto the new upstream commit, fixing any conflicts in the commits above.
2. Update the commit and date above.
3. In kun: `cargo test --workspace` and the reftests. Upstream's API
   changes show up as build errors in `crates/layout/src/text.rs` and
   `crates/shell/src/omnibox.rs`.
